Two distinct label types on the plan — which are we talking about?

The codebase handles these separately with different placement logic. The centroid-drift algorithm we just designed targets Type 1. Your question may be about Type 2 — or both.

A

Type 1 only — stand number labels (2041, 2042, 2043…)

The large parcel designation centred inside the polygon. This is what the centroid-drift algorithm targets. "2043A" and "2043E" in this context would be parcels on a subdivision plan — sub-stands of an original stand.

B

Type 2 only — beacon suffix labels (A, B, C… placed near corner symbols)

The small single-letter or short-code label placed just inside the parcel boundary next to each beacon circle. These are currently edge-aligned and can go near-vertical on steep edges. The centroid-drift concept doesn't apply here — they need to stay near their corner.

C

Both — apply east-west orientation constraint to all label types

Type 1 gets the full centroid-drift treatment. Type 2 (corner suffix labels) gets its own simpler fix: constrain their angle to ±45° from horizontal, placed just inside the polygon edge near the beacon, no edge-following for steep corners.
