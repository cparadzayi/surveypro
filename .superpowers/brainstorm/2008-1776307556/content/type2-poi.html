POI for Type 2 — how it differs from Type 1

Type 1 (stand number) drifts to the POI. Type 2 (beacon suffix) uses the POI to determine direction only — the label stays near its corner, but is pushed inward along a ±45°-clamped vector toward the POI instead of following the edge.

Type 2 algorithm — POI-directed corner placement

  1. Compute POI for the parcel (or use centroid for speed — nearly identical for regular parcels)
  2. Direction vector = beacon corner → POI. This points inward, away from the boundary.
  3. Clamp angle to ±45° from horizontal. If the raw vector is steeper (e.g. 80°), rotate it to ±45°.
  4. Place label at a short fixed distance (1× beacon radius + small clearance) along that clamped vector. Render horizontally (0°) — the direction only governs where the label sits, not its rotation.
  5. Check: wholly inside polygon + no collision with edge labels. If fail → try small angular perturbations (±10°, ±20°) still within the ±45° band.
  6. Fallback: if all angles fail, nudge further inward along the clamped direction (centroid-drift style) until it fits.

Key difference from Type 1: the label stays near its corner (essential for field identification) — the POI only sets the inward push direction. Type 1 can travel all the way to the POI; Type 2 travels only as far as needed to clear the boundary and any other labels.
