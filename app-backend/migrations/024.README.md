# Migration 024: Land Parcels Duplicate Cleanup & Prevention

## 🎯 **Purpose**

This migration cleans up duplicate land parcels and implements safeguards to prevent future duplicates:

1. **Removes duplicate parcels** - Same stand number within a project
2. **Adds unique constraint** - Prevents duplicate stand numbers per project
3. **Prevents polygon overlaps** - Detects and blocks overlapping parcel boundaries

---

## 🔍 **What Gets Fixed**

### **Problem 1: Duplicate Stand Numbers**
Multiple parcels with the same stand number in one project:
```
Project 23:
  - Stand 2836 (ID: 9)
  - Stand 2836 (ID: 10)  ← Duplicate!
  - Stand 2836 (ID: 11)  ← Duplicate!
```

**Solution:** Keeps the most recently created parcel, deletes older duplicates

---

### **Problem 2: Polygon Overlays**
Parcels with overlapping boundaries (geometric conflicts):
```
Parcel A (Stand 2428): overlaps Parcel B (Stand 2429) by 15.6 m²
```

**Solution:** Trigger prevents inserting/updating parcels that overlap existing ones

## 🛡️ **Safeguards Added**

### **1. Unique Constraint**
```sql
ALTER TABLE land_parcels
  ADD CONSTRAINT unique_project_stand
  UNIQUE (project_id, stand);
```

**Effect:**
- ✅ Prevents duplicate stand numbers within the same project
- ✅ Allows same stand number in different projects
- ❌ Blocks: `INSERT INTO land_parcels (project_id, stand) VALUES (23, '2836')` (if 2836 already exists in project 23)

**Error Message:**
```
Parcel with stand "2836" already exists in this project
```

---

### **2. Spatial Overlap Prevention**
```sql
CREATE TRIGGER prevent_parcel_overlap
  BEFORE INSERT OR UPDATE OF geom ON land_parcels
  FOR EACH ROW
  EXECUTE FUNCTION check_parcel_overlap();
```

**Effect:**
- ✅ Detects polygon overlaps using PostGIS `ST_Overlaps()`
- ✅ Allows small overlaps < 1m² (digitization tolerance)
- ❌ Blocks overlaps > 1m²

**Error Message:**
```
Parcel "2428" overlaps with existing parcel "2429" by 15.60 m². 
Please adjust boundaries.
HINT: Check your parcel boundaries in QGIS to avoid overlaps
```

```sql
SELECT project_id, stand, COUNT(*) as count
FROM land_parcels
GROUP BY project_id, stand
HAVING COUNT(*) > 1;
```
**Expected:** 0 rows

---

### **Check for Overlapping Parcels**
```sql
SELECT 
  a.stand as parcel_a,
  b.stand as parcel_b,
  ST_Area(ST_Intersection(a.geom, b.geom)) as overlap_area_m2
FROM land_parcels a
JOIN land_parcels b ON a.project_id = b.project_id AND a.id < b.id
WHERE ST_Overlaps(a.geom, b.geom)
  AND ST_Area(ST_Intersection(a.geom, b.geom)) > 1.0;
```
**Expected:** 0 rows (or only small overlaps < 1m²)

## ⚠️ **Important Notes**

### **Duplicate Deletion Strategy**
The migration keeps the **most recent** parcel based on `created_at`:
```
Stand 2836 duplicates:
  - ID 11 (created: 2025-11-12 07:00:00) ✅ KEEP
  - ID 10 (created: 2025-11-12 06:55:00) ❌ DELETE
  - ID 9  (created: 2025-11-12 06:50:00) ❌ DELETE
```

**Rationale:**
- Most recent parcel likely has the latest/correct data
- User's most recent action should be preserved
- Older versions are typically superseded

---

### **Overlap Tolerance**
Small overlaps (< 1m²) are allowed:
```
Overlap 0.5m² → ✅ Allowed (digitization precision)
Overlap 2.0m² → ❌ Blocked (actual conflict)
```

**Why?**
- Digitization in QGIS has pixel-level precision (~0.1-0.5m)
- Snapping tolerance can create small overlaps
- True conflicts are typically > 1m²
