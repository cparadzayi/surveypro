# Migration 027: Survey Type, Stand Reference, and Township

**Date:** 2025-01-22  
**Purpose:** Add persistent project information fields to survey_projects table  
**Status:** Ready to deploy

---

## Overview

This migration adds three new columns to the `survey_projects` table to store persistent project information captured at Project Setup (Step 0) that will auto-populate throughout the cadastral workflow.

---

## Changes

### **New Columns:**

1. **survey_type** (VARCHAR(50))
   - Survey type classification
   - Values: subdivision, mining-lease, state-land, municipal-land, private-land, servitude, replacement, other
   - Used for: Template selection, AI/ML suggestions, document generation
   - Nullable: Yes (for backward compatibility with existing projects)

2. **stand_reference** (VARCHAR(255))
   - Stand/Reference number or identifier
   - Examples: "STANDS 1-50", "STAND 9723", "Mining Lease No.44"
   - Used for: Auto-population in all documents (Field Book, Reports, Certificate)
   - Nullable: Yes (for backward compatibility)

3. **township** (VARCHAR(255))
   - Township name or description
   - Examples: "Shabani Mine Surface Rights A", "Gweru Township", "Gwelo Township Lands"
   - Used for: Complete "Survey Of" descriptions in certificates
   - Nullable: Yes (optional field)

### **Indexes Created:**

1. **idx_survey_projects_survey_type**
   - On: survey_type column
   - Purpose: Fast filtering/reporting by survey type

2. **idx_survey_projects_stand_reference**
   - On: stand_reference column
   - Purpose: Fast searching by stand/reference number

## Deployment Steps

1. **Backup database**
   ```bash
   pg_dump -U postgres surveypro > backup_before_027.sql
   ```

2. **Apply migration**
   ```bash
   psql -U postgres -d surveypro -f 027.do.sql
   ```

3. **Verify migration**
   ```sql
   -- Check columns
   SELECT column_name, data_type, is_nullable 
   FROM information_schema.columns 
   WHERE table_name = 'survey_projects' 
   AND column_name IN ('survey_type', 'stand_reference', 'township');
   
   -- Check indexes
   SELECT indexname, indexdef 
   FROM pg_indexes 
   WHERE tablename = 'survey_projects' 
   AND indexname LIKE 'idx_survey_projects_%';
   ```

4. **Test application**
   - Create new project with all fields
   - Verify data saves to database
   - Verify DSG Certificate auto-populates
   - Test with existing projects (should work unchanged)

5. **Monitor**
   - Check application logs
   - Monitor database performance
   - Verify no errors in production
