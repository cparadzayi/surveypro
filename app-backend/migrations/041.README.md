# Migration 041: Workflow States Table

## Purpose

Creates the `workflow_states` table to persist cadastral workflow data for each project. This enables:
- Resume workflow from any step
- Persist imported CSV points with status (F/P)
- Store calculations, adjustments, and intermediate results
- Track workflow progress and completed steps

## Problem Solved

**Before:** Workflow data only existed in browser memory (lost on refresh)
**After:** All workflow data persisted in database, survives page refresh, can be resumed

## Schema

```sql
workflow_states (
  id SERIAL PRIMARY KEY,
  project_id INTEGER UNIQUE REFERENCES survey_projects(id),
  current_step VARCHAR(100),
  step_data JSONB,           -- All workflow data
  completed_steps TEXT[],     -- Array of completed steps
  created_at TIMESTAMP,
  updated_at TIMESTAMP
)
```

## Step Data Structure

The `step_data` JSONB column contains workflow data organized by step:

```json
{
  "csv-import": {
    "points": [
      {
        "id": "BP001",
        "y": 97538.004,
        "x": 2247107.872,
        "status": "F",
        "description": "50mm Iron Pipe in Concrete",
        "survey_date": "2025-12-05T22:00:00.000Z"
      }
    ],
    "coordinate_count": 540,
    "file_imported_at": "2025-12-06T03:30:00.000Z"
  },
  "field-book": {
    "surveyor_info": { ... },
    "document_url": "..."
  },
  "calculations-part1": {
    "adjusted_coordinates": [ ... ]
  },
  "control-point-selection": {
    "selected_control_points": [ ... ],
    "central_meridian": 31
  }
}
```

## Indexes

1. **project_id** - Fast lookup by project (most common query)
2. **current_step** - Filter by step for monitoring
3. **updated_at** - Track recent activity
4. **step_data (GIN)** - Fast JSONB queries for specific data

## Usage

### Save Workflow State
```javascript
await api.patch(`/survey-projects/${projectId}/workflow`, {
  step: 'csv-import',
  action: 'complete',
  metadata: {
    points: [...],
    coordinate_count: 540
  }
});
```

### Load Workflow State
```javascript
const response = await api.get(`/survey-projects/${projectId}/workflow`);
const workflowState = response.data.workflow_state;
```

## Performance

- Table size: ~10-50 KB per project (JSONB compressed)
- Query time: <5ms with indexes
- Update frequency: 1-10 times per workflow step

## Maintenance

**Cleanup old workflow states (>6 months):**
```sql
DELETE FROM workflow_states 
WHERE updated_at < NOW() - INTERVAL '6 months'
AND project_id IN (
  SELECT id FROM survey_projects 
  WHERE last_used < NOW() - INTERVAL '6 months'
);
```

## Notes

- Each project has exactly ONE workflow_states row (UNIQUE constraint)
- step_data grows as workflow progresses (starts small, accumulates data)
- On DELETE CASCADE: workflow state deleted when project deleted
- updated_at auto-updates via trigger
