# Migration 053: Automatic Area Calculation via Database Triggers

## Purpose
Implement automatic area calculation from geometry using PostgreSQL triggers to eliminate data redundancy and ensure consistency.

## Problem Statement
Currently, the `land_parcels` table stores computed area values (`area_m2`, `area_ha`, `perimeter_m`, etc.) that are redundant with the geometry data. This violates database normalization principles and can lead to:
- **Data inconsistency**: Area values can become out of sync with geometry
- **Manual updates required**: Need to call `/calculate-areas` endpoint after geometry changes
- **Redundant storage**: Same information stored twice

## Solution
Use PostgreSQL triggers to automatically compute area, perimeter, centroid, and closure error whenever geometry is inserted or updated.

## Changes

### 1. Trigger Function: `auto_calculate_parcel_metrics()`
Automatically computes:
- **area_m2**: Area in square meters using `ST_Area(geom)`
- **area_ha**: Area in hectares (area_m2 / 10000)
- **perimeter_m**: Perimeter in meters using `ST_Perimeter(geom)`
- **centroid_y**: Y-coordinate of centroid using `ST_Y(ST_Centroid(geom))`
- **centroid_x**: X-coordinate of centroid using `ST_X(ST_Centroid(geom))`
- **closure_error_m**: Calculated from residuals if available in metadata

### 2. Trigger: `land_parcel_auto_calculate`
Fires **BEFORE INSERT OR UPDATE** of `geom` column on `land_parcels` table.

### 3. Backfill Existing Data
Recalculates all existing parcels to ensure consistency.

## Benefits
1. ✅ **Single Source of Truth**: Geometry is the only authoritative data
2. ✅ **Always Accurate**: Area automatically reflects geometry changes
3. ✅ **No Manual Intervention**: No need to call `/calculate-areas` endpoint
4. ✅ **Better Normalization**: Follows 3NF principles
5. ✅ **Performance**: Computed values are cached for fast queries
6. ✅ **Audit Trail**: `updated_at` timestamp tracks geometry changes

## Migration Safety
- ✅ Non-destructive: Keeps existing columns
- ✅ Backward compatible: Existing queries continue to work
- ✅ Automatic backfill: Updates all existing parcels
- ✅ Can be rolled back via undo migration

## Testing
After migration, verify:
```sql
-- Test 1: Insert new parcel - area should auto-calculate
INSERT INTO land_parcels (project_id, stand, geom)
VALUES (1, 'TEST-001', ST_GeomFromText('POLYGON((0 0, 100 0, 100 100, 0 100, 0 0))', 22291));

SELECT stand, area_m2, area_ha, perimeter_m FROM land_parcels WHERE stand = 'TEST-001';
-- Expected: area_m2 = 10000, area_ha = 1.0, perimeter_m = 400

-- Test 2: Update geometry - area should recalculate
UPDATE land_parcels 
SET geom = ST_GeomFromText('POLYGON((0 0, 50 0, 50 50, 0 50, 0 0))', 22291)
WHERE stand = 'TEST-001';

SELECT stand, area_m2, area_ha, perimeter_m FROM land_parcels WHERE stand = 'TEST-001';
-- Expected: area_m2 = 2500, area_ha = 0.25, perimeter_m = 200

-- Cleanup
DELETE FROM land_parcels WHERE stand = 'TEST-001';
```
