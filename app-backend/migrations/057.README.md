# Migration 057: Remove land_parcels_qgis View

## Decision: Use Direct Table Access

After careful consideration, we've decided to **drop the `land_parcels_qgis` view** and use the `land_parcels` table directly in QGIS.

## Rationale

### ❌ Problems with View Approach

1. **User Confusion**: Two layers (`land_parcels` vs `land_parcels_qgis`) - which one to use?
2. **Schema-per-surveyor Overhead**: Views must be created/maintained in every surveyor schema
3. **Metadata Preservation**: View rules can complicate `metadata.vertices` updates
4. **Synchronization Risk**: View rules can fail silently, causing data inconsistencies
5. **Unnecessary Complexity**: Modern QGIS handles generated columns correctly

### ✅ Benefits of Direct Table Access

1. **Simpler**: One table, one source of truth
2. **Faster**: No view overhead or rule processing
3. **Reliable**: Direct INSERT/UPDATE to table
4. **Metadata Safe**: `metadata.vertices` preserved correctly
5. **QGIS 3.x+ Compatible**: Automatically ignores `GENERATED ALWAYS` columns

## Technical Background

### Original Problem (2023)
QGIS 2.x couldn't insert into tables with `GENERATED ALWAYS` columns, causing errors like:
```
ERROR: cannot insert into column "area_m2"
DETAIL: Column "area_m2" is a generated column.
```

### Modern Solution (2024+)
QGIS 3.x+ **automatically detects and excludes** generated columns from INSERT/UPDATE statements. No view needed!

## What This Migration Does

1. **Drops `land_parcels_qgis` views** from all surveyor schemas
2. **Drops `create_land_parcels_qgis_view()` function**
3. **Updates table comments** with direct QGIS usage instructions

## Updated QGIS Workflow

### Before (with view):
```
1. Add layer: land_parcels_qgis (editable view)
2. Add layer: land_parcels (read-only, for viewing areas)
3. Digitize in land_parcels_qgis
4. Switch to land_parcels to see calculated areas
```

### After (direct table):
```
1. Add layer: land_parcels (single table)
2. Digitize polygons with stand designation
3. Optionally add vertex labels in metadata
4. Save - areas auto-calculate via trigger
5. Refresh to see calculated areas
```

## Vertex Labeling Integration

With direct table access, storing vertex labels in `metadata.vertices` is straightforward:

```sql
-- QGIS digitizes parcel 1463 with shared beacons
INSERT INTO land_parcels (project_id, stand, designation, geom, metadata)
VALUES (
  123,
  '1463',
  '1463',
  ST_GeomFromText('POLYGON((...))', 22291),
  '{"vertices": [
    {"id":"1463A","y":18862.52,"x":2268555.01,"order":1},
    {"id":"1462A","y":18875.14,"x":2268541.39,"order":2},
    {"id":"1463C","y":18849.88,"x":2268541.39,"order":3},
    {"id":"1464C","y":18837.26,"x":2268555.01,"order":4}
  ]}'::jsonb
);
```

The trigger automatically calculates `area_m2`, `area_ha`, `perimeter_m`, and `centroid_y/x`.

## QGIS Setup Instructions

### 1. Remove Old Layer (if exists)
- Remove `land_parcels_qgis` layer from QGIS
- Remove any bookmarks or saved connections to the view

### 2. Add Direct Table Layer
```
Layer → Add Layer → Add PostGIS Layers...
- Connection: [Your surveyor schema connection]
- Schema: surveyor_surveyor_kuda (or your schema)
- Table: land_parcels ✓
- Geometry column: geom
- SRID: 22291 (Cape Lo 31)
```

### 3. Configure Layer Properties
- **Display Name**: Land Parcels
- **Form**: Configure attribute form for easy data entry
- **Labels**: Use `stand` or `designation` field

### 4. Digitize Parcels
1. Enable editing (pencil icon)
2. Add polygon feature
3. Fill in attributes:
   - `stand`: Parcel number (e.g., "1463")
   - `designation`: Same as stand
   - `project_id`: Your project ID
   - `metadata`: (Optional) Add vertex labels as JSONB
4. Save edits

### 5. View Calculated Areas
- Refresh layer (F5)
- Open attribute table
- See `area_m2`, `area_ha`, `perimeter_m` columns (read-only)

## Vertex Labeling in QGIS

To add shared beacon labels, you can:

### Option A: Manual JSONB Entry
In attribute form, set `metadata` field:
```json
{"vertices": [
  {"id":"1463A","y":18862.52,"x":2268555.01,"order":1},
  {"id":"1462A","y":18875.14,"x":2268541.39,"order":2},
  {"id":"1463C","y":18849.88,"x":2268541.39,"order":3},
  {"id":"1464C","y":18837.26,"x":2268555.01,"order":4}
]}
```

### Option B: Backend Function (Recommended)
After digitizing in QGIS, use backend function to populate vertices:
```sql
SELECT update_parcel_vertices(
  (SELECT id FROM land_parcels WHERE stand = '1463'),
  ARRAY['1463A', '1462A', '1463C', '1464C']
);
```

### Option C: Frontend Tool (Future)
A future enhancement could add a UI tool to:
1. Load parcel from QGIS
2. Click vertices to label them
3. Save back to `metadata.vertices`

## Migration Safety

- ✅ **Non-destructive**: Only drops views, not data
- ✅ **Backward compatible**: Existing parcels unaffected
- ✅ **Rollback available**: `npm run migrate:undo` restores views
- ✅ **QGIS compatible**: Works with QGIS 3.x+

If you need to restore the view (not recommended):
```bash

```

This will recreate `land_parcels_qgis` views in all surveyor schemas.
