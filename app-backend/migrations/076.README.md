# Migration 076: Update Outside Figure Metadata with Beacon Names

## Purpose

Update existing Outside Figure parcels to include beacon names (id/name) in their `metadata.residuals.edges` array. This ensures the GeoPDF "Outside Figure Data" table displays the correct beacon order starting with the actual beacon names (e.g., M8, 2836B, 2835D) instead of generic letter labels (A, B, C).

## Problem

The backend area computation service (`compute.js`) was updated to preserve beacon `id` and `name` properties when building edge data. However, existing Outside Figure parcels in the database were created before this update and only have `{y, x}` coordinates in their edge data, without beacon identifiers.

This caused the frontend to fall back to generic letter labels (A-Z, A1-Z1, etc.) when rendering the Outside Figure Data table in the GeoPDF, instead of using the actual beacon names from the area and consistency data.

## Solution

This migration:

1. **Identifies Outside Figure parcels** by checking:
   - `stand ILIKE '%outside figure%'`
   - `designation ILIKE '%outside figure%'`
   - `metadata->>'isOutsideFigure' = TRUE`

2. **Extracts beacon information** from `metadata.cape_lo_points` which contains the full point data including beacon IDs/names

3. **Rebuilds the edges array** in `metadata.residuals.edges` with:
   - `from.id` and `from.name` - Source beacon identifier
   - `to.id` and `to.name` - Destination beacon identifier
   - `from.y`, `from.x` - Source coordinates
   - `to.y`, `to.x` - Destination coordinates
   - `distance` - Edge length in meters
   - `bearingDeg` - Bearing in degrees (south-based azimuth)

4. **Updates the parcel metadata** with the enriched edge data

## Files Modified

- `076.do.sql` - Main migration script
- `076.undo.sql` - Rollback script (clears edges array)

## Related Changes

**Backend:** `app-backend/src/routes/compute.js` (lines 175-185)
- Modified to preserve `id` and `name` properties when building observations
- New parcels will automatically have beacon names in edge data

**Frontend:** `app-frontend/src/views/modules/cadastral-standard/SurveyPlanMapView.vue` (lines 4250-4280)
- Uses `edge.from.id` and `edge.to.id` to extract beacon names
- Falls back to generic letters only if beacon names are missing

## Expected Results

After running this migration:

1. ✅ Outside Figure parcels have beacon names in `metadata.residuals.edges`
2. ✅ GeoPDF "Outside Figure Data" table shows correct beacon order (M8 first)
3. ✅ Constants column displays actual beacon names instead of generic letters
4. ✅ Area and consistency data is used as single source of truth

## Verification

```sql
-- Check Outside Figure parcel metadata
SELECT 
  id,
  stand,
  jsonb_array_length(metadata->'residuals'->'edges') AS edge_count,
  metadata->'residuals'->'edges'->0->'from'->>'id' AS first_beacon,
  metadata->'residuals'->'edges'->0->'to'->>'id' AS second_beacon
FROM land_parcels
WHERE stand ILIKE '%outside figure%';
```

Expected output:
```
 id  |      stand        | edge_count | first_beacon | second_beacon
-----+-------------------+------------+--------------+---------------
 81  | Outside Figure    |     40     | M8           | 2836B
```

## Rollback

To undo this migration:

```bash
psql -d surveypro -f 076.undo.sql
```

This will clear the edges array for Outside Figure parcels, reverting to the pre-migration state.

## Notes

- This migration only affects **existing** Outside Figure parcels
- **New parcels** created after the backend update will automatically have beacon names
- The migration is **idempotent** - safe to run multiple times
- If a parcel doesn't have `cape_lo_points` in metadata, it will be skipped with a warning
