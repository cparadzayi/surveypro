# Collating the Beacon Comparison Report and Report of Survey into the Comprehensive PDF

**Date:** 2026-07-22
**Status:** Design approved, pending implementation plan

## Problem

`Comprehensive_Latest.pdf` today collates five sections — Cover, Field Book,
Coordinate List, Calculations Part 1, and Areas & Consistency — but neither the
**Beacon Comparison Report** (SI 727 Section 67(5) Helmert / W-test comparison of
found beacons) nor the narrative **Report of Survey** appears in it. Surveyors
want both folded into the collated record:

- The **Beacon Comparison Report** (about the found beacons) collated **before**
  the Calculations, and a copy saved in the Calculations output folder.
- The **Report of Survey** (narrative detailing the issues around the actual
  survey) collated at the **bottom** of the document, and kept in the Reports
  output folder.

## Current state (what the code actually does)

- **One** "Report on Survey" is produced by `ReportOnSurveyView.vue`, with a
  user-selectable format:
  - **Narrative** (`utils/reportOnSurveyNarrativeGenerator.ts`) — prose: purpose,
    survey basis, found/placed beacon narrative, comments. **No comparison table.**
  - **Structured** (`utils/reportOnSurveyGenerator.ts`) — numbered sections plus a
    `BEACON COMPARISON (SI 727 Section 67(5))` block: method line, adjustment /
    W-test summary, the `Beacon / Original Y,X / New Y,X / Δ` table, and a
    conclusion (`addBeaconComparison` + `addBeaconComparisonTable`).
  - It saves to `output/reports/` (`documentType: 'report-on-survey'`).
- The beacon comparison also appears as a plain found/placed coordinate table
  inside Calculations Part 1 — this is **not** the Section 67(5) comparison and is
  out of scope here.
- The collated document is assembled by a two-pass pipeline:
  - `utils/TwoPassDocumentGenerator.ts` — Pass 1 measures each section's real page
    count; Pass 2 renders with accurate cross-references. Page scheme: Field Book
    `E1…En`; Coordinate List starts at `100`; Calculations starts at
    `coordinateListEnd + 1`; Areas starts at `calculationsEnd + 1`. The Coordinate
    List cross-references each point to its **calculation page number**
    (`calculationsPageLookup`), which is generated by the calc generator for a
    given `startingPage`.
  - `utils/comprehensive-document.ts` (`generateWithTwoPass`) wraps the two-pass
    generator, merges the Cover, and returns `{ pdf, measurements, sections }`.
  - `composables/useComprehensivePDF.ts` (`generateComprehensiveLatestPDF`) appends
    the Areas & Consistency section to the two-pass body, saves the final PDF to
    the **Calculations folder** (`documentType: 'calculations-part1'`,
    `Comprehensive_Latest.pdf`, `overwrite: true`), and returns `areasOnlyBlob`.
  - `composables/useSurveyRecordOutputs.ts` (`saveSurveyRecordSections`) writes each
    section as its own file into its output subfolder (Field Book, Coordinate List,
    Calculations, Areas).
  - Callers: `views/modules/cadastral-standard/MapLibreAreaView.vue` and
    `SurveyPlanMapView.vue`.
- `workflowState.reportOnSurvey` (`types/cadastral.ts` `ReportOnSurveyData`) carries
  `beacons`, `beaconComparison`, and the narrative fields (purpose, surveyBasis,
  comments, etc.), so both reports can be regenerated from workflow state at
  collation time.

## Goal

Collate two artifacts into `Comprehensive_Latest.pdf`, both generated from
`workflowState.reportOnSurvey` at build time (self-contained — no dependency on
the user having visited the Report on Survey step), with graceful skip when the
underlying data is absent.

## Design

### Final assembly order and page numbering

| # | Section | Page numbers |
|---|---------|--------------|
| 1 | Cover | — |
| 2 | Field Book | `E1…En` |
| 3 | Coordinate List | `100…C` |
| 4 | **Beacon Comparison Report** (NEW) | `C+1 … C+K` |
| 5 | Calculations Part 1 | `C+K+1 …` (shifted by `K`) |
| 6 | Areas & Consistency | continues |
| 7 | **Report of Survey — narrative** (NEW) | continues to end |

The **Beacon Comparison Report is numbered in sequence** (K pages). Its presence
shifts the Calculations start page from `C+1` to `C+K+1`. Because the Coordinate
List's point→calc-page lookup is generated from the calc generator *at that
shifted start page*, the cross-references remain correct — they simply point to
the shifted pages. Areas (`calcEnd + 1`) and total pages flow from the shifted
calc end automatically. The narrative Report of Survey is numbered as a
continuation after Areas and is referenced by nothing, so it is the lowest-risk
insertion.

### New / reused generators

- **`utils/beaconComparisonReportGenerator.ts` (new).** A standalone generator that
  renders **only** the Section 67(5) comparison: method line, adjustment / W-test
  summary, the `Beacon / Original Y,X / New Y,X / Δ` table, and the conclusion.
  Signature roughly `generateBeaconComparisonReportPDF(reportData, options,
  startingPage) → { pdf: Blob, pageCount: number }`, jsPDF-based, stamping
  in-sequence page numbers from `startingPage`. The shared rendering is **extracted
  from** `reportOnSurveyGenerator.ts` (`addBeaconComparison` /
  `addBeaconComparisonTable`) so the structured Report on Survey and this new
  standalone report render the comparison identically (single source of truth).
- **Narrative Report of Survey.** Reuse `generateNarrativeReportOnSurveyPDF(reportData,
  options)`; extend it to accept a `startingPage` so its page numbers continue the
  sequence after Areas.

### Data flow

Both reports build their `ReportOnSurveyData` from `workflowState.reportOnSurvey`
at collation time. Extract a small pure adapter (e.g.
`buildReportDataFromWorkflow(workflowState)`) so the two caller views and any tests
share one construction path and it is unit-testable. Graceful skip rules:

- No `reportOnSurvey.beaconComparison` (or no `beacons` with `originalData`
  coordinates) → **no** Beacon Comparison Report is inserted; `K = 0`; Calculations
  keeps its unshifted start; no `BeaconComparison.pdf` written.
- Essentially empty report data → **no** narrative appended; no `ReportOnSurvey.pdf`
  written.

### Integration points

- **`TwoPassDocumentGenerator.ts`** — thread the beacon comparison inputs through
  `TwoPassDocumentData`. In `measurePass`, after the Coordinate List, render the
  Beacon Comparison Report once to get `K`; set `calcStartPage = coordinateListEnd
  + K + 1`. In `renderPass`, render the beacon report at `coordinateListEnd + 1`
  and splice its blob into the merged body between Coordinate List and
  Calculations. Add `beaconComparison` to the returned `sections` (for the folder
  copy) and reflect `K` in `measurements.totalPages`. When there is no comparison
  data, `K = 0` and behaviour is identical to today.
- **`comprehensive-document.ts`** — extend `ComprehensiveDocumentData` /
  `generateWithTwoPass` to carry the report data through to the two-pass generator,
  and surface the new `beaconComparison` section blob in its return `sections`.
- **`useComprehensivePDF.ts`** — after the Areas merge, append the narrative Report
  of Survey (numbered from Areas' end page) to the merged blob to form the final
  `Comprehensive_Latest.pdf`; also produce the narrative blob so the caller can
  write it to the Reports folder. `areasOnlyBlob` is unchanged.
- **`useSurveyRecordOutputs.ts` / `saveSurveyRecordSections`** — add the Beacon
  Comparison Report as a Calculations-folder copy (`documentType:
  'calculations-part1'`, `fileName: 'BeaconComparison.pdf'`, `overwrite: true`) and
  the narrative as a Reports-folder copy (`documentType: 'report-on-survey'`,
  `fileName: 'ReportOnSurvey.pdf'`, `overwrite: true`). Both best-effort — a failed
  write is recorded and never aborts the others.
- **Callers** (`MapLibreAreaView.vue`, `SurveyPlanMapView.vue`) — build the report
  data via the adapter and pass it into the generator; pass the narrative blob and
  beacon blob into the section-save step.

### Folder copies

- `output/calculations/BeaconComparison.pdf` — the standalone Section 67(5) report.
- `output/reports/ReportOnSurvey.pdf` — the narrative, kept in sync with the
  collated copy (complements the existing manual save from the Report on Survey
  step).

## Testing

- **Unit (vitest):**
  - `beaconComparisonReportGenerator` — returns `pageCount ≥ 1` and a non-empty
    blob when `beaconComparison` + `beacons` are present; renders the method line,
    Δ table, and conclusion; returns an empty/skip signal when data is absent.
  - `buildReportDataFromWorkflow` adapter — maps `workflowState.reportOnSurvey` to
    `ReportOnSurveyData`; empty-state detection for the graceful-skip rules.
  - Update `utils/__tests__/twoPassSections.test.ts` for the new section presence
    and the shifted Calculations start page (`C+K+1`).
- **Manual QA (end to end):**
  1. A project with a completed Found Beacons comparison and a filled Report on
     Survey → generate the Comprehensive PDF → confirm the Beacon Comparison Report
     appears immediately before Calculations with in-sequence page numbers, the
     Calculations pages are shifted by `K`, the Coordinate List's calc-page
     cross-references still resolve to the correct calc pages, and the narrative
     Report of Survey appears at the very bottom.
  2. Confirm `output/calculations/BeaconComparison.pdf` and
     `output/reports/ReportOnSurvey.pdf` are written.
  3. A project **without** a beacon comparison → the report is skipped, Calculations
     starts unshifted, cross-references are unchanged, and no `BeaconComparison.pdf`
     is written.

## Non-goals

- No change to the plain found/placed beacon coordinate table already inside
  Calculations Part 1.
- No change to the Helmert / W-test math (`surveyMath.js`, `si727.js`) or the
  Compare engine.
- The structured Report on Survey format and the Report on Survey step UI are
  unchanged (they keep rendering the comparison inline via the shared renderer).
